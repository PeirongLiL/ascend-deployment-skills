# 实践案例，仅用于排查思路

- 案例 A：某节点物理卡 3 出现不可纠正 HBM ECC（0x80e01801），高累计错误，显存测试失败。更换卡后 VDie ID 变化、PCIe 插槽不变；52 GiB、3 轮校验零错误，测试后 ECC 零。该记录不代表当前硬件状态。
- 案例 B：另一节点 Device 3 在 NPU 健康 OK 时出现 RoCE DOWN、Receive timeout、Rx LoL 告警，其余端口 UP。问题定位到高速链路，不能仅凭此判断光模块、光纤、网卡或交换机哪一件损坏。远程复位未解决；后续现场处理后端口 UP，但未记录具体更换部件。
- Kimi 一次 Profiler 显示高通信等待，但双节点/全规模微基准和计数器未支持持续硬件故障。不要根据一次慢 rank 更换硬件。
- NPU RoCE 数据面与主机 bond 控制网可能独立，必须采当前配置识别，不能根据 2×25GbE bond 推导所有 collective 都受 50Gbps 限制。

容器若只映射物理卡 3，内部可能显示 device 0；报告必须保留映射。更换卡后计数重置不可直接当“故障自行消失”。
